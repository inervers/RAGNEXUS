Multi-Agent 系统是 LLM 应用的高级架构。相比单一 Agent 处理所有任务，Multi-Agent 将复杂任务拆解给多个专业化 Agent 协作完成，每个 Agent 只负责自己擅长的领域。

典型的 Agent 分工模式：
- 研究员 Agent：负责检索和分析信息，输出关键论点
- 写作者 Agent：基于研究结果生成内容
- 审核员 Agent：检查内容质量，给出改进建议
- Supervisor Agent：负责任务分解和结果汇总

Agent 间通信协议的设计至关重要。结构化通信（使用 JSON Schema 定义接口）比非结构化通信（纯文本传递）更可靠，因为明确的接口契约减少了解析错误，允许接收方精确提取需要的信息。

状态机是 Multi-Agent 流程控制的有效模式。将整个工作流定义为有限状态集（如 INIT → RESEARCH → WRITE → REVIEW → FINALIZE），通过守卫机制控制状态转移条件。状态机相比线性流水线的优势在于支持重试、回退和分支。

持久化记忆让 Agent 能记住历史交互，避免重复犯同样的错误。Agent 每次行动前检索相关记忆，行动后将结果存入记忆库。研究表明，带记忆的 Agent 在需要多轮迭代的任务中表现显著优于无记忆版本。

监控评估是 Multi-Agent 系统不可缺失的部分。通过全链路追踪记录每个 Agent 的输入输出和耗时，可以识别系统瓶颈。
